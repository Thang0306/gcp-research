# Production Generative AI on Google Cloud (Vertex AI / Gemini Enterprise Agent Platform): Claude on Vertex, Gemini on Vertex, Claude Code with Vertex — learning resources and production facts (as of 2026-11-06)

Note for the report writer: Google renamed "Vertex AI" to **"Gemini Enterprise Agent Platform"** (short: "Agent Platform") at Google Cloud Next '26 (April 22, 2026). Most docs URLs moved from `cloud.google.com/vertex-ai/generative-ai/docs/...` to `docs.cloud.google.com/gemini-enterprise-agent-platform/...`. Old URLs redirect. The API host is still `aiplatform.googleapis.com` and the IAM role is still `roles/aiplatform.user`. Many search results, courses and books still say "Vertex AI". In these notes "Vertex AI" and "Agent Platform" mean the same product.

## Q1. Which official Google and Anthropic docs cover Claude on Vertex AI end to end (Model Garden enablement, regions incl. asia-southeast1 / global, quotas, anthropic[vertex] SDK, auth, prompt caching, batch, token counting, pricing, provisioned throughput, 429s)?

### Takeaway
The core reading set is small and authoritative: Anthropic's "Claude Models on Google Cloud (Google managed)" page plus Google's Claude partner-model pages (overview, quotas, batch predictions, prompt caching) and Google's data-residency page. The single most important production fact for a Singapore-resident health-insurance workload is that **regional endpoints (like `asia-southeast1`) only serve Claude Sonnet 4.6 and older models (per Anthropic)**, while the newest models need the `global` or `us`/`eu` multi-region endpoints. Google's data-residency table appears to contradict this for Singapore, so this must be checked in Model Garden before you design the system.

### Cited Findings

**Two different "Claude on Google Cloud" offerings now exist (new in 2026)**
- Anthropic now documents two offerings. In **"Claude Models on Google Cloud (Google managed)"**, Google runs Claude inside Agent Platform. You call it through `aiplatform.googleapis.com` `:rawPredict`/`:streamRawPredict` endpoints with the `AnthropicVertex` SDK client, Agent Platform IAM roles, Google-managed rate limits, and billing as Agent Platform usage. In **"Claude Models on Google Cloud (Anthropic managed)"**, Anthropic runs the Claude API on `claude.googleapis.com`. That offering uses the `AnthropicGoogleCloud` client, `roles/claude.user`/`claude.admin`/`claude.viewer`, Anthropic-managed rate limits, and billing through Google Cloud Marketplace. It also creates a new Anthropic organization and always uses the `global` location. — [Anthropic: Claude Models on Google Cloud overview](https://platform.claude.com/docs/en/build-with-claude/claude-models-on-google-cloud/overview)
- How to tell which offering you use: if the request URL contains `.../publishers/anthropic/models/{model}` and ends in `:rawPredict`, it is Google managed ("classic Vertex"). If it goes to `claude.googleapis.com/.../invoke/v1/messages`, it is Anthropic managed. — [Anthropic overview](https://platform.claude.com/docs/en/build-with-claude/claude-models-on-google-cloud/overview)

**Setup, SDK and auth (Google managed = what a "Claude on Vertex" project uses)**
- Prerequisites: a project that can use Agent Platform, the gcloud CLI, an IAM role with `aiplatform.endpoints.predict` (for example `roles/aiplatform.user`), and Google credentials. The SDK uses ADC (`gcloud auth application-default login`). The cURL examples use `gcloud auth print-access-token`, which uses the gcloud CLI's own login, not ADC. — [Anthropic: Google managed page](https://platform.claude.com/docs/en/build-with-claude/claude-models-on-google-cloud/google-managed)
- Python install: `pip install -U "anthropic[vertex]"`. Client: `from anthropic import AnthropicVertex; client = AnthropicVertex(project_id="MY_PROJECT_ID", region="global")`. After that, `client.messages.create(model="claude-opus-5-5", max_tokens=..., messages=[...])` works the same as the normal Messages API. TypeScript uses `@anthropic-ai/vertex-sdk`. — [Anthropic: Google managed page](https://platform.claude.com/docs/en/build-with-claude/claude-models-on-google-cloud/google-managed)
- REST differences from the Claude API: the model goes in the URL, not the body. `anthropic_version` goes in the body, set to `vertex-2023-10-16` or the API version `2026-10-21`. Streaming uses a separate `:streamRawPredict` endpoint. — [Anthropic: Google managed page](https://platform.claude.com/docs/en/build-with-claude/claude-models-on-google-cloud/google-managed)
- Model IDs: Claude 4.6 and later use plain IDs (`claude-sonnet-4-6`, `claude-opus-5-5`, `claude-sonnet-5`, `claude-haiku-5-5`). Older models use `@` before the snapshot date (`claude-sonnet-4-5@20250929`, `claude-haiku-4-5@20251001`, `claude-opus-4-5@20251101`). Sonnet 4.5, Sonnet 4, Opus 4.1 and Opus 4 are marked deprecated. — [Anthropic: Google managed page](https://platform.claude.com/docs/en/build-with-claude/claude-models-on-google-cloud/google-managed)
- Google sets the lifecycle and retirement dates for Claude on Agent Platform, and these "can differ from the Claude API schedule." — [Anthropic: Google managed page](https://platform.claude.com/docs/en/build-with-claude/claude-models-on-google-cloud/google-managed)
- Enabling models: request access to each Claude model in Model Garden ("search Claude, request access, wait for approval (may take 24-48 hours)"). — [Claude Code docs: Agent Platform](https://code.claude.com/docs/en/google-vertex-ai)

**Endpoints, regions, pricing premium, data residency**
- Three endpoint types. **Global** (`region="global"`, host `aiplatform.googleapis.com`) is recommended for availability, and requests may go to any region. **Multi-region** (`"us"`/`"eu"`, hosts `aiplatform.us.rep.googleapis.com` / `aiplatform.eu.rep.googleapis.com`). **Regional** (for example `"us-east5"`, host `{region}-aiplatform.googleapis.com`) is for single-region residency. — [Anthropic: Google managed page](https://platform.claude.com/docs/en/build-with-claude/claude-models-on-google-cloud/google-managed)
- "Multi-region and regional endpoints cost 10 percent more than global endpoints." The premium applies to Sonnet 4.5 and later. "Provisioned throughput needs a regional endpoint." — [Anthropic: Google managed page](https://platform.claude.com/docs/en/build-with-claude/claude-models-on-google-cloud/google-managed)
- **"Regional endpoints serve Claude Sonnet 4.6 and earlier models only. For newer models, use a global or multi-region endpoint."** — [Anthropic: Google managed page](https://platform.claude.com/docs/en/build-with-claude/claude-models-on-google-cloud/google-managed)
- Google's data-residency page says requests to a `global` endpoint "may be processed in any Google Cloud location around the world" and "don't provide any data residency guarantees." Data at rest stays in the chosen location whatever endpoint you call, but ML processing location follows the endpoint. — [Google: Where your data lives and is processed](https://docs.cloud.google.com/gemini-enterprise-agent-platform/resources/data-residency?hl=en)
- **CONFLICT:** the same Google data-residency page (as read by our fetch tool) lists Singapore (asia-southeast1) ML-processing commitments for Claude Opus 5.5, Sonnet 5.5, Sonnet 5, Opus 5, Fable 5.1, Fable 5, Opus 4.6, Opus 4.5, Sonnet 4.5 (deprecated) and Claude 3 Haiku (deprecated). That contradicts Anthropic's "regional = Sonnet 4.6 and earlier" statement. Google's quotas page lists only Opus 4.6, Sonnet 4.6, Opus 4.5, Sonnet 4.5, Claude 3.5 Sonnet and Claude 3 Haiku for asia-southeast1. A third-party tracker lists a regional asia-southeast1 endpoint for Sonnet 5 (updated July 2026). — [Google data residency](https://docs.cloud.google.com/gemini-enterprise-agent-platform/resources/data-residency?hl=en); [Google Claude quotas](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/partner-models/claude/quotas); [modelavailability.com (third party)](https://modelavailability.com/models/anthropic/claude-sonnet-5); contradicted by [Anthropic: Google managed page](https://platform.claude.com/docs/en/build-with-claude/claude-models-on-google-cloud/google-managed)
- Request payload limit on Agent Platform is 30 MB. Large PDFs or many images can hit this before the token limit. — [Anthropic: Google managed page](https://platform.claude.com/docs/en/build-with-claude/claude-models-on-google-cloud/google-managed)
- 1M-token context on Vertex for Fable 5.1/5, Opus 5.5/5/4.8/4.7/4.6, Sonnet 5.5/5/4.6 and Haiku 5.5. Other models (for example Sonnet 4.5) have 200k. — [Anthropic: Google managed page](https://platform.claude.com/docs/en/build-with-claude/claude-models-on-google-cloud/google-managed)

**Feature support on Vertex (important for design)**
- Supported: Messages API, prompt caching, extended thinking, tool use (bash, browser use, computer use, memory, text editor, web search tools), citations, **structured outputs**. — [Anthropic: Google managed page](https://platform.claude.com/docs/en/build-with-claude/claude-models-on-google-cloud/google-managed)
- **Not supported:** URL sources for images/documents, the Files API, server-side code execution, web fetch, advisor, Agent Skills, the MCP connector, programmatic tool calling, the **Message Batches API**, the Models/Admin/Usage APIs, Claude Managed Agents, and the server-side `fallbacks` parameter. For fallback, Anthropic says to use the client-side fallback pattern. — [Anthropic: Google managed page](https://platform.claude.com/docs/en/build-with-claude/claude-models-on-google-cloud/google-managed)

**Quotas (Claude on Vertex)**
- Quota types are QPM (queries per minute) and TPM. Newer models have separate input TPM and output TPM. Quotas are per model per region (regional, multi-region or global). Models launched after May 26, 2026 use **shared lineage quotas** on global/multi-region, so all versions in a family share one bucket. To find them, filter by `base_model`, for example `anthropic-claude-opus`. — [Google: Quotas for Anthropic Claude models](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/partner-models/claude/quotas)
- asia-southeast1 default quotas: Opus 4.6 is 200 QPM / 2,000,000 input TPM / 200,000 output TPM. Sonnet 4.6 is 1,500 QPM / 1,500,000 input TPM / 150,000 output TPM. Opus 4.5 is 200 / 2M / 200k. Sonnet 4.5 is 1,500 / 1.5M / 150k. — [Google: Claude quotas](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/partner-models/claude/quotas)
- Global defaults are much larger. Sonnet 5.5 and Sonnet 5 are 2,500 QPM / 25M input TPM / 2.5M output TPM. Opus 5.5 is 2,000 / 20M / 2M. Haiku 5.5 is 3,000 / 30M / 3M. Sonnet 4.6 is 1,500 / 1.5M / 150k. — [Google: Claude quotas](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/partner-models/claude/quotas)
- For newer models, input TPM counts uncached input plus cache-write tokens. **Cache-read tokens are not counted.** The Quotas page usage display "may be inaccurate", so use the token counting API or the `token_count` metrics in Metrics Explorer. Increases are requested on the Cloud console Quotas page. — [Google: Claude quotas](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/partner-models/claude/quotas)
- Anthropic: "Google Cloud manages rate limits and quotas" for the Google-managed offering. — [Anthropic: Google managed page](https://platform.claude.com/docs/en/build-with-claude/claude-models-on-google-cloud/google-managed)
- Community reports show Claude quotas "stuck at 0" in all regions for some new projects, so the quota request may need a support ticket (anecdotal). — [Google Developer forum thread](https://discuss.google.dev/t/claude-sonnet-4-5-quota-stuck-at-0-on-all-regions-cannot-increase/355205)

**Batch predictions for Claude (replaces Message Batches API on Vertex)**
- Supported models include Sonnet 5.5, Fable 5.1, Sonnet 5, Opus 5.5, Opus 5, Fable 5, Opus 4.8, Opus 4.7, Opus 4.6, Sonnet 4.6, Opus 4.5, Sonnet 4.5, Haiku 5.5, Haiku 4.5 and Claude 3.5 Haiku. — [Google: Batch predictions with Claude](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/partner-models/claude/batch)
- Input is a BigQuery table (`custom_id` plus `request` columns, where `request` is the Claude API body) or a JSONL file in Cloud Storage. Output can be BigQuery (`response(JSON)` column) or JSONL. The batch job and the BigQuery input table must be in the same region. **The global endpoint is not supported for batch.** The default is 4 concurrent batch jobs per project. Results arrive "after all rows have completed or after 24 hours, whichever comes first." — [Google: Claude batch](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/partner-models/claude/batch)
- The Python sample uses the **google-genai** SDK (`client.batches.create(model="publishers/anthropic/models/claude-3-5-haiku", src="gs://.../input.jsonl", config=CreateBatchJobConfig(dest=...))`), not the anthropic SDK. — [Google: Claude batch](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/partner-models/claude/batch)

**Prompt caching for Claude on Vertex**
- Use explicit `cache_control` breakpoints. The default TTL is 5 minutes, and `"ttl": "1h"` extends it to 1 hour. Each hit refreshes the TTL. All requests must use the same `cache_control` placement and identical content. On the Vertex page, a 1-hour cache write costs 100% above base input, and a 5-minute write costs 25% above. — [Google: Claude prompt caching](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/partner-models/claude/prompt-caching) (details from search snippets; page not fully fetched)
- Anthropic's docs said automatic caching was not yet on Vertex (snippet). Use explicit breakpoints. — [Anthropic prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching?hl=en-CA) (snippet; may have changed)

**Billing, logging, compliance**
- Google bills Claude usage. Prices are on Google's Generative AI pricing page (Claude section), and they also depend on endpoint type. — [Anthropic: Google managed page](https://platform.claude.com/docs/en/build-with-claude/claude-models-on-google-cloud/google-managed); [Google pricing](https://cloud.google.com/vertex-ai/generative-ai/pricing#claude-models)
- To log prompts and completions, turn on Agent Platform **request-response logging**. Anthropic recommends keeping at least 30 days of logs. — [Anthropic: Google managed page](https://platform.claude.com/docs/en/build-with-claude/claude-models-on-google-cloud/google-managed)
- Google's Claude overview page mentions SSE streaming, pay-as-you-go or Provisioned Throughput, 30-day request-response logging, inference metadata logging (token counts, latency, errors, without prompt text), and FedRAMP High. — [Google: Claude models on Agent Platform](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/partner-models/claude)
- Release notes: Claude Opus 4.8 (May 28, 2026), Fable 5 (Jun 9), Sonnet 5 (Jun 30), Opus 5 (Jul 24), Fable 5.1 (Sep 1), Opus 5.5 (Sep 22), Sonnet 5.5 (Sep 28), Haiku 5.5 (Oct 7, 2026) were added to Model Garden. — [Agent Platform release notes](https://docs.cloud.google.com/gemini-enterprise-agent-platform/release-notes)

**Retries/429 for Claude**
- Claude Code's troubleshooting section says: for 429 on regional endpoints, make sure the models are supported in that region, and "consider switching to `CLOUD_ML_REGION=global` for better availability". — [Claude Code docs: Agent Platform](https://code.claude.com/docs/en/google-vertex-ai)
- Google's 2026 resilience blog says: do not retry immediately on 429/503. Use exponential backoff with jitter (Tenacity or the SDK's `HttpRetryOptions`), use the global endpoint, smooth traffic, use caching, use Priority PayGo / Provisioned Throughput for critical traffic, and use Batch/Flex for offline work. It also mentions Apigee circuit breaking (`apigee-samples/llm-circuit-breaking`). — [Google Cloud blog, Mar 12, 2026](https://cloud.google.com/blog/products/ai-machine-learning/reduce-429-errors-on-vertex-ai)

### Inferences
- For a Vietnamese TPA with Singapore residency, a realistic production design is: Claude **Sonnet 4.6** on the `asia-southeast1` regional endpoint for PHI-bearing calls, with the 10% regional premium and lower regional quotas (1,500 QPM / 1.5M input TPM). Newer models (Sonnet 5/5.5) would be used only on `global` for non-sensitive work, or after confirming Singapore support in Model Garden. The Anthropic-vs-Google conflict above is the first thing to check, because it changes which models are allowed.
- Provisioned Throughput needs a regional endpoint. So if the TPA needs guaranteed capacity and residency, PT in asia-southeast1 is the natural option, limited to the models served there.
- Prompt caching matters twice on Vertex. It cuts cost, and cache reads do not count toward input TPM quota. A long, stable system prompt plus schema for claim extraction should be put before the cache breakpoint.
- Because the Message Batches API and the `fallbacks` parameter are not available, nightly re-processing of claims should use Vertex batch predictions (regional, not global). Model fallback (for example Claude to Gemini) must be written in your own code.

### Gaps
- The exact list of Claude models currently served on the asia-southeast1 **regional** endpoint could not be confirmed, because the sources conflict (see above). Verify in Model Garden ("Supported regions") in the actual project.
- Claude per-token prices on Vertex (global vs regional) were not fetched. Use the Google pricing page.
- Claude Provisioned Throughput details (GSU size per Claude model, minimum term) were not fetched.
- Google's Claude token-counting page (`count-tokens` endpoint for partner models) was not fetched. Claude Code docs only confirm that token counting needs `aiplatform.endpoints.predict`.
- How `max_tokens` counts toward output TPM quota is not stated on the quotas page.

## Q2. How do you configure Claude Code to use Vertex AI (env vars, region, model pinning, IAM)? Which official pages and tutorials exist?

### Takeaway
One official page covers it fully: **code.claude.com/docs/en/google-vertex-ai** ("Claude Code on Google Cloud's Agent Platform"). You can use the `/login` wizard (or `/setup-vertex`), or set `CLAUDE_CODE_USE_VERTEX=1`, `CLOUD_ML_REGION`, and `ANTHROPIC_VERTEX_PROJECT_ID`, and pin models with `ANTHROPIC_DEFAULT_OPUS_MODEL` / `_SONNET_MODEL` / `_HAIKU_MODEL`. The IAM role is `roles/aiplatform.user`.

### Cited Findings
- Prerequisites: a GCP account with billing, a project with the Agent Platform API enabled (`gcloud services enable aiplatform.googleapis.com`), Claude models enabled in Model Garden, gcloud installed, and quota in the region you choose. — [Claude Code docs](https://code.claude.com/docs/en/google-vertex-ai)
- Wizard path: run `claude`, choose **3rd-party platform → Google Vertex AI**, then choose ADC, a service-account key file, or existing env credentials. The wizard asks for project and region, checks which Claude models the project can call, lets you pin them, and saves everything to the `env` block of `~/.claude/settings.json`. `/setup-vertex` reopens the wizard. — [Claude Code docs](https://code.claude.com/docs/en/google-vertex-ai)
- Manual env vars: `CLAUDE_CODE_USE_VERTEX=1`, `CLOUD_ML_REGION=global` (or `us`/`eu`, or a region such as `us-east5`), `ANTHROPIC_VERTEX_PROJECT_ID=YOUR-PROJECT-ID`, and optionally `ANTHROPIC_VERTEX_BASE_URL` for gateways. Per-model region overrides use `VERTEX_REGION_CLAUDE_*` (examples: `VERTEX_REGION_CLAUDE_HAIKU_4_5=us-east5`, `VERTEX_REGION_CLAUDE_4_6_SONNET=europe-west1`). If `CLOUD_ML_REGION` is invalid or unset, it falls back to `us-east5`. — [Claude Code docs](https://code.claude.com/docs/en/google-vertex-ai)
- Claude Code sends requests to the project in `ANTHROPIC_VERTEX_PROJECT_ID`, even if `GOOGLE_CLOUD_PROJECT` or the credential file names a different project. X.509 Workload Identity Federation works through `GOOGLE_APPLICATION_CREDENTIALS`. `gcpAuthRefresh` (for example `"gcloud auth application-default login"`) refreshes expired credentials automatically. — [Claude Code docs](https://code.claude.com/docs/en/google-vertex-ai)
- Prompt caching is on by default. `DISABLE_PROMPT_CACHING=1` turns it off, and `ENABLE_PROMPT_CACHING_1H=1` asks for a 1-hour TTL at a higher write price. "To raise your rate limits, contact Google Cloud support." `/logout` is not available on Vertex. — [Claude Code docs](https://code.claude.com/docs/en/google-vertex-ai)
- **Model pinning** is strongly recommended for teams. Without pins, `opus` resolves to Opus 5.5 and `sonnet` resolves to Sonnet 4.5 on Vertex. The defaults are primary `claude-opus-5-5` and small/fast `claude-sonnet-4-5@20250929`. Example pins: `ANTHROPIC_DEFAULT_OPUS_MODEL='claude-opus-4-8'`, `ANTHROPIC_DEFAULT_SONNET_MODEL='claude-sonnet-5'`, `ANTHROPIC_DEFAULT_HAIKU_MODEL='claude-haiku-4-5@20251001'`. `ANTHROPIC_MODEL` sets the primary model. Warning: if you do not pin, you are billed at the Opus rate. — [Claude Code docs](https://code.claude.com/docs/en/google-vertex-ai)
- Startup model checks: if the default model is not enabled, Claude Code falls back for the session (earlier versions first, then Sonnet). If an admin disables a model mid-session, it switches to another model unless you pinned that tier. `CLAUDE_CODE_DISABLE_MODEL_ACCESS_FALLBACK=1` makes refused requests fail instead. `availableModels` + `enforceAvailableModels` in managed settings sets an org allowlist (v2.1.287+). — [Claude Code docs](https://code.claude.com/docs/en/google-vertex-ai)
- Verify with `/status`. It should show `API provider: Google Vertex AI`, plus the GCP project, region and model. — [Claude Code docs](https://code.claude.com/docs/en/google-vertex-ai)
- IAM: `roles/aiplatform.user`, which includes `aiplatform.endpoints.predict`, the permission needed for model calls and token counting. A custom role can hold only that permission. Anthropic recommends a dedicated GCP project for Claude Code to simplify cost tracking. — [Claude Code docs](https://code.claude.com/docs/en/google-vertex-ai)
- 1M context is the default on Vertex for Fable, Sonnet 5+ and Opus 4.7+ (no `[1m]` suffix). Opus 4.6 and Sonnet 4.6 need the `[1m]` suffix. `CLAUDE_CODE_DISABLE_1M_CONTEXT=1` keeps a 200K window. — [Claude Code docs](https://code.claude.com/docs/en/google-vertex-ai)
- Troubleshooting: "Could not load the default credentials" means you should run `gcloud auth application-default login` or set `GOOGLE_APPLICATION_CREDENTIALS`. A 404 "model not found" means the model is not enabled, or it is not available in that location (some models are global/multi-region only). For 429, check that both the primary and small/fast models exist in the region, or use `global`. — [Claude Code docs](https://code.claude.com/docs/en/google-vertex-ai)
- Tutorials and videos: Anthropic webinar "Agents with Claude on Vertex" (June 25, 2025) covers Claude Code with Claude on Vertex AI and integrating Claude with ADK. — [Anthropic webinar page](https://www.anthropic.com/webinars/agents-with-claude-on-vertex). There is also a 30-minute workshop by Ivan Nardini (Google Cloud DevRel) on building and deploying a multi-agent system with Claude + ADK + MCP + Agent Engine + A2A (third-party write-up). — [dev.to write-up](https://dev.to/bokuno_log/building-production-ai-agents-with-google-cloud-adk-claude-30-min-workshop-1lll)
- Third-party region guides exist (Japanese and English), for example "Region Settings for Using Claude on Vertex AI | global vs us & eu". — [clauder-navi.com](https://www.clauder-navi.com/en/vertex-claude-region/); [Classmethod setup guide (JP)](https://dev.classmethod.jp/articles/vertex-ai-model-garden-claude-setup-guide/)

### Inferences
- For the learner (Singapore, regulated data), set `CLOUD_ML_REGION=global` for coding work only if source code is not considered regulated data. Otherwise use `asia-southeast1` and pin `ANTHROPIC_MODEL=claude-sonnet-4-6` (a regional-capable model per Anthropic), and set `ANTHROPIC_DEFAULT_HAIKU_MODEL` / small-fast to a model that also exists in that region. Otherwise background tasks can 404 or 429.
- The default small/fast model on Vertex (`claude-sonnet-4-5@20250929`) is marked deprecated in Anthropic's model table. This is another reason to pin explicitly.

### Gaps
- No official Google codelab specifically for "Claude Code + Vertex AI" was found.
- The full list of `VERTEX_REGION_CLAUDE_*` variable names is on the env-vars reference page, which was not fetched.

## Q3. What are the best deep resources for Gemini on Vertex AI in production (google-genai SDK, structured output, function calling, context caching, batch, grounding, Live API, safety, quotas/DSQ, Provisioned Throughput, versioning/retirement)?

### Takeaway
Use the **Google Gen AI SDK (`google-genai`) reference docs** together with the Agent Platform docs pages for **Standard PayGo / DSQ**, **Model versions and lifecycle**, and **data residency**. The biggest production surprise for this learner: **Gemini 2.5 Pro, 2.5 Flash and 2.5 Flash-Lite were retired on Vertex on October 20, 2026.** The reference project's "Gemini 2.5 Flash/Pro" setup is already outdated and must move to Gemini 3.x/4 models, checking which of them have Singapore ML processing.

### Cited Findings

**SDK status**
- The Generative AI module of the Vertex AI SDK (`vertexai.generative_models` and related) was deprecated on June 24, 2025 and scheduled for removal on June 24, 2026. The migration target is the Google Gen AI SDK. — [Google: Generative AI deprecations](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/deprecations)
- On Sep 18, 2026, the Python SDK package `google-cloud-agentplatform` was split from `google-cloud-aiplatform`, and Agent Platform SDK 2.0.1 "moved generative AI modules to the Google Gen AI SDK." — [Agent Platform release notes](https://docs.cloud.google.com/gemini-enterprise-agent-platform/release-notes)
- The current google-genai docs create the enterprise/Vertex client with `genai.Client(enterprise=True, project=..., location=...)` and env vars `GOOGLE_GENAI_USE_ENTERPRISE`, `GOOGLE_CLOUD_PROJECT`, `GOOGLE_CLOUD_LOCATION`. Some examples (Veo) still use `genai.Client(vertexai=True)`. — [Google Gen AI SDK docs](https://googleapis.github.io/python-genai/)
- Structured output: `response_mime_type='application/json'` plus `response_schema=<PydanticModel>`, or `response_json_schema=<dict>`. The docs advise not repeating the schema in the prompt, because "output quality may suffer". — [Google Gen AI SDK docs](https://googleapis.github.io/python-genai/)
- Function calling: passing Python functions in `tools` turns on automatic function calling by default. Disable it with `AutomaticFunctionCallingConfig(disable=True)`. `maximum_remote_calls` limits loops (default 10). — [Google Gen AI SDK docs](https://googleapis.github.io/python-genai/)
- Context caching: `client.caches.create(model=..., config=types.CreateCachedContentConfig(..., ttl='3600s'))`, then `cached_content=cache.name` in generate calls. — [Google Gen AI SDK docs](https://googleapis.github.io/python-genai/)
- Batch: `client.batches.create(model=..., src='bq://project.dataset.table')` or a GCS source. — [Google Gen AI SDK docs](https://googleapis.github.io/python-genai/)
- Async: `client.aio.models.generate_content(...)`. Close it with `await aclient.aclose()` or use `async with Client().aio`. Safety: `types.SafetySetting(category='HARM_CATEGORY_HATE_SPEECH', threshold='BLOCK_ONLY_HIGH')`. Tokens: `client.models.count_tokens(...)`. "Compute tokens is only supported in Gemini Enterprise Agent Platform." — [Google Gen AI SDK docs](https://googleapis.github.io/python-genai/)
- The SDK has native retry behavior through `HttpRetryOptions` in client parameters. — [Google Cloud blog, Mar 2026](https://cloud.google.com/blog/products/ai-machine-learning/reduce-429-errors-on-vertex-ai)

**Model versions and retirement**
- Lifecycle table (Agent Platform). `gemini-2.5-pro`, `gemini-2.5-flash` and `gemini-2.5-flash-lite` were **retired Oct 20, 2026**. The recommended upgrades are `gemini-3.8-flash` or `gemini-3.5-flash` / `gemini-3.5-flash-lite` (or Gemma 4 for Flash-Lite). Current models: `gemini-4-argon` (Oct 13, 2026), `gemini-3.8-flash` (Sep 2, 2026), `gemini-3.8-live` (Sep 24, 2026), `gemini-3.5-flash` (May 19, 2026), `gemini-3.5-flash-lite` (Jul 21, 2026), `gemini-3.1-flash-lite` (May 7, 2026). `gemini-3.6-flash` retires **Nov 19, 2026** and `gemini-3.7-flash` retires Jan 28, 2027. `gemini-live-2.5-flash-native-audio` retires Dec 13, 2026. Gemini 2.0 Flash/Flash-Lite were retired Jun 1, 2026. Embeddings: `gemini-embedding-2` (Apr 22, 2026) and `gemini-embedding-001` (no sooner than May 20, 2028). — [Google: Model versions and lifecycle](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/learn/model-versioning)
- Lifecycle policy: stable models are available for at least 12 months, and retirement dates "won't be moved to an earlier date". Shorter-lived models get at least 45 days' notice. — [Google: Model versions and lifecycle](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/learn/model-versioning)
- Gemini API (AI Studio) and Vertex can have **different** retirement dates for the same model. — [Google Developer forum](https://discuss.google.dev/t/gemini-2-5-flash-lite-retirement-date-different-for-gemini-api-vs-vertex-ai/389197)
- Gemini 3.6 Flash and 3.5 Flash-Lite (Jul 21, 2026) brought breaking changes to sampling/penalty parameters and to how a final model-role turn is handled. — [Agent Platform release notes](https://docs.cloud.google.com/gemini-enterprise-agent-platform/release-notes)

**Data residency for Gemini in Singapore**
- Gemini models with Singapore (asia-southeast1) ML-processing commitments are `gemini-4-argon`, `gemini-3.5-flash`, and `gemini-2.5-flash` (now retired). `gemini-3.8-flash` was not listed for Singapore in our fetch. Global endpoints give no residency guarantee. — [Google data residency](https://docs.cloud.google.com/gemini-enterprise-agent-platform/resources/data-residency?hl=en)

**Quotas, DSQ, consumption options**
- Newer Gemini models use **Dynamic Shared Quota (DSQ)**, where PayGo capacity is shared among all customers per model and region, so there are no per-project quota increase requests. Older/non-Gemini models use the standard per-project quotas. — [search snippets: Google quotas/DSQ pages](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/quotas)
- **Standard PayGo usage tiers** (organization-level, based on 30-day spend, measured per model on the **global** endpoint): Tier 1 ($10–$250) is 500k TPM for Pro/Argon and 2M for Flash/Flash-Lite. Tier 2 ($250–$2,000) is 1M / 4M. Tier 3 ($2,000–$50,000) is 2M / 10M. Tier 4 (> $50,000, added Sep 10, 2026) is 10M / 50M. There is no separate RPM limit. — [Google: Standard PayGo](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/standard-paygo); [release notes](https://docs.cloud.google.com/gemini-enterprise-agent-platform/release-notes)
- "If you receive a 429 error, it doesn't indicate that you've hit a fixed quota." It means temporary contention. Traffic above your tier is served opportunistically and throttled first. Second-level spikes can be throttled even when the per-minute average is fine. Single-region endpoints have "the highest likelihood of 429 errors". Mitigations: exponential backoff, the global endpoint, smoothing, Priority PayGo, Provisioned Throughput. — [Google: Standard PayGo](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/standard-paygo)
- Priority PayGo became GA on May 14, 2026 (US/EU multi-region added Sep 9). The Deferred tier is in Preview (50% discount, Sep 2). Provisioned Throughput gained a tokens-per-second latency SLA (May 20, 2026) and order management features. — [Agent Platform release notes](https://docs.cloud.google.com/gemini-enterprise-agent-platform/release-notes)
- Hybrid consumption advice: PT for essential real-time traffic, Priority PayGo for spiky critical traffic, Standard for general traffic, Batch/Flex for latency-tolerant traffic. Batch is managed with retries over about 24 hours. — [Google Cloud blog, Mar 12, 2026](https://cloud.google.com/blog/products/ai-machine-learning/reduce-429-errors-on-vertex-ai)

## Q9. Production interview-style questions (with short answers and sources)

### Takeaway
These 24 questions cover what an interviewer at a GCP-based insurance/TPA AI team is likely to ask about Vertex AI, Claude on Vertex and Gemini.

### Cited Findings
1. **Q: How is a Claude request on Vertex different from a request to api.anthropic.com?** A: The model is in the URL (`.../publishers/anthropic/models/{model}:rawPredict`), `anthropic_version` (`vertex-2023-10-16` or `2026-10-21`) is in the body, streaming uses `:streamRawPredict`, auth is a Google OAuth token / ADC (not an API key), and the SDK client is `AnthropicVertex(project_id, region)`. — [Anthropic](https://platform.claude.com/docs/en/build-with-claude/claude-models-on-google-cloud/google-managed)
2. **Q: Which pip package and client do you use?** A: `pip install -U "anthropic[vertex]"`, then `from anthropic import AnthropicVertex`. — [Anthropic](https://platform.claude.com/docs/en/build-with-claude/claude-models-on-google-cloud/google-managed)
3. **Q: What IAM role does a service account need to call Claude or Gemini?** A: `roles/aiplatform.user` (it includes `aiplatform.endpoints.predict`, also needed for token counting). — [Claude Code docs](https://code.claude.com/docs/en/google-vertex-ai); [Anthropic](https://platform.claude.com/docs/en/build-with-claude/claude-models-on-google-cloud/google-managed)
4. **Q: Global vs multi-region vs regional endpoint — trade-offs?** A: Global has the best availability and no residency guarantee. Multi-region (`us`/`eu`) gives broad-geo residency. Regional gives single-region residency. Multi-region and regional cost +10%, and Provisioned Throughput needs regional. — [Anthropic](https://platform.claude.com/docs/en/build-with-claude/claude-models-on-google-cloud/google-managed); [Google data residency](https://docs.cloud.google.com/gemini-enterprise-agent-platform/resources/data-residency?hl=en)
5. **Q: We must keep processing in Singapore. Can we use the newest Claude model?** A: Per Anthropic, regional endpoints serve only Sonnet 4.6 and earlier, so use e.g. `claude-sonnet-4-6` on `asia-southeast1`. Google's residency table lists newer models for Singapore, so verify in Model Garden. Never use `global` for PHI. — [Anthropic](https://platform.claude.com/docs/en/build-with-claude/claude-models-on-google-cloud/google-managed); [Google data residency](https://docs.cloud.google.com/gemini-enterprise-agent-platform/resources/data-residency?hl=en)
6. **Q: Why does `claude-sonnet-4-5-20250929` return 404 on Vertex?** A: Pre-4.6 IDs use `@`: `claude-sonnet-4-5@20250929`. A 404 can also mean the model is not enabled in Model Garden or not offered in that region. — [Anthropic overview](https://platform.claude.com/docs/en/build-with-claude/claude-models-on-google-cloud/overview); [Claude Code docs](https://code.claude.com/docs/en/google-vertex-ai)
7. **Q: How are Claude quotas measured on Vertex, and how do you raise them?** A: QPM plus input TPM and output TPM, per model per region (shared lineage buckets for models after May 26, 2026). Cache reads don't count toward input TPM. Request increases on the Cloud console Quotas page. — [Google Claude quotas](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/partner-models/claude/quotas)
8. **Q: What are the default Claude Sonnet 4.6 quotas in asia-southeast1?** A: 1,500 QPM, 1.5M input TPM, 150k output TPM. — [Google Claude quotas](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/partner-models/claude/quotas)
9. **Q: Can you use Anthropic's Message Batches API on Vertex?** A: No. Use Vertex batch predictions: BigQuery or GCS JSONL input with `custom_id`, output to BQ or GCS, same region as the BQ table, no global endpoint, 4 concurrent jobs by default, results within 24h. — [Anthropic](https://platform.claude.com/docs/en/build-with-claude/claude-models-on-google-cloud/google-managed); [Google Claude batch](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/partner-models/claude/batch)
10. **Q: How do you do prompt caching for Claude on Vertex and what does it cost?** A: Add `cache_control` breakpoints after a stable prefix (system prompt, schema, few-shots). TTL is 5 min by default, or `"ttl": "1h"`. Writes cost +25% (5m) or +100% (1h) over base input, and reads are cheap and excluded from TPM quota. — [Google Claude prompt caching](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/partner-models/claude/prompt-caching); [Google Claude quotas](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/partner-models/claude/quotas)
11. **Q: Which Claude API features are NOT available on Vertex?** A: Files API, URL image/document sources, server code execution, web fetch, MCP connector, Agent Skills, programmatic tool calling, Message Batches, Models/Admin/Usage APIs, Managed Agents, and the server-side `fallbacks` param. — [Anthropic](https://platform.claude.com/docs/en/build-with-claude/claude-models-on-google-cloud/google-managed)
12. **Q: A 40-page scanned claim PDF fails on Vertex but the token count is fine. Why?** A: The Agent Platform request payload limit is 30 MB. Split or compress, or send page images in chunks (parallel chunked calls). — [Anthropic](https://platform.claude.com/docs/en/build-with-claude/claude-models-on-google-cloud/google-managed)
13. **Q: Gemini returns 429 but our dashboard shows we're under quota. What's happening?** A: Under Standard PayGo/DSQ a 429 is not a fixed quota. It is temporary contention on shared capacity, and bursts can be throttled even if the per-minute average is fine. Fix: backoff with jitter, smooth traffic, use the global endpoint (if residency allows), Priority PayGo, or Provisioned Throughput. — [Google Standard PayGo](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/standard-paygo); [Google blog](https://cloud.google.com/blog/products/ai-machine-learning/reduce-429-errors-on-vertex-ai)
14. **Q: What are Standard PayGo usage tiers?** A: Org-level tiers by 30-day spend, measured on the global endpoint per model. For example, Tier 1 ($10–250) gives 2M TPM for Flash, and Tier 4 (>$50k) gives 50M TPM for Flash / 10M for Pro/Argon. — [Google Standard PayGo](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/standard-paygo)
15. **Q: Describe a correct retry policy for Vertex LLM calls.** A: Never retry immediately on 429/503. Use exponential backoff with jitter and a max delay and max attempts (SDK `HttpRetryOptions`, Tenacity, or ADK Reflect-and-Retry), add per-request timeouts, and add a circuit breaker / client-side model fallback (Apigee sample). — [Google blog 2026](https://cloud.google.com/blog/products/ai-machine-learning/reduce-429-errors-on-vertex-ai); [Google blog (429s)](https://cloud.google.com/blog/products/ai-machine-learning/learn-how-to-handle-429-resource-exhaustion-errors-in-your-llms)
16. **Q: Which SDK should new Gemini code use, and what happened to `vertexai.generative_models`?** A: `google-genai` (`from google import genai`). The Vertex AI SDK's generative module was deprecated Jun 24, 2025, with removal scheduled Jun 24, 2026. — [Google deprecations](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/deprecations)
17. **Q: How do you force JSON that matches a Pydantic schema with Gemini?** A: `GenerateContentConfig(response_mime_type="application/json", response_schema=MyModel)` (or `response_json_schema`), and don't repeat the schema in the prompt. — [Google Gen AI SDK](https://googleapis.github.io/python-genai/)
18. **Q: How does Gemini explicit context caching work in google-genai?** A: `client.caches.create(model, config=CreateCachedContentConfig(contents/system_instruction, ttl="3600s"))`, then pass `cached_content=cache.name`. — [Google Gen AI SDK](https://googleapis.github.io/python-genai/)
19. **Q: Our code uses `gemini-2.5-flash` on Vertex. Is that OK in Nov 2026?** A: No. It was retired on Vertex on Oct 20, 2026. Migrate to `gemini-3.8-flash` or `gemini-3.5-flash` (for Singapore residency, 3.5 Flash or 4 Argon have SG ML-processing commitments) and re-run evals. — [Model lifecycle](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/learn/model-versioning); [Google data residency](https://docs.cloud.google.com/gemini-enterprise-agent-platform/resources/data-residency?hl=en)
20. **Q: What is Google's model retirement policy?** A: Stable models are available at least 12 months, and retirement dates are never moved earlier. Shorter-lived models get at least 45 days' notice. Vertex and Gemini API dates can differ. — [Model lifecycle](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/learn/model-versioning); [forum](https://discuss.google.dev/t/gemini-2-5-flash-lite-retirement-date-different-for-gemini-api-vs-vertex-ai/389197)
21. **Q: How do you point Claude Code at Vertex?** A: `CLAUDE_CODE_USE_VERTEX=1`, `CLOUD_ML_REGION=global|us|eu|<region>`, `ANTHROPIC_VERTEX_PROJECT_ID=<project>`, and ADC via `gcloud auth application-default login`. Pin `ANTHROPIC_DEFAULT_OPUS_MODEL` / `_SONNET_MODEL` / `_HAIKU_MODEL`, then verify with `/status`. — [Claude Code docs](https://code.claude.com/docs/en/google-vertex-ai)
22. **Q: Why pin models in Claude Code for a team on Vertex?** A: Without pins, the aliases resolve to built-in defaults (`opus` → Opus 5.5) that may not be enabled, may fall back silently per session, and bill at Opus rates. Pins control upgrades and cost. — [Claude Code docs](https://code.claude.com/docs/en/google-vertex-ai)
23. **Q: How would you evaluate an LLM claim-extraction pipeline on GCP?** A: Use the Gen AI evaluation service. Start with adaptive rubrics / `GENERAL_QUALITY` and add custom metrics. For agents, use tool-call correctness and grounding metrics. Note the GenAI Client eval is Preview, and the GA module lacks adaptive rubrics. — [Google eval overview](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/evaluation-overview); [Define metrics](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/determine-eval)
24. **Q: How do you get audit logs of prompts and responses for Claude on Vertex?** A: Turn on Agent Platform request-response logging (Anthropic recommends keeping ≥30 days). Inference metadata logging gives token counts and latency without content. — [Anthropic](https://platform.claude.com/docs/en/build-with-claude/claude-models-on-google-cloud/google-managed); [Google Claude page](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/partner-models/claude)
